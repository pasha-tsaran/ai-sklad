# Только утверждённая база знаний AI Support

Для технической помощи профиль `ai-support` использует только коллекцию
**«AI Support (склад) — инструкции 1 линии технической поддержки»**.

```text
85cda3aa-b854-4c26-9948-12da742277ef
```

Права администратора Open WebUI и доступ пользователя к другим базам сотрудников
не расширяют этот набор источников. Принадлежность разрешённой коллекции и доступ
проверяются до выдачи текста инструменту или модели.

Эта настройка ограничивает поиск и чтение утверждёнными источниками.

## Один этап настройки в Open WebUI

Настройку выполняет администратор. Используйте существующие инструмент, функцию
и профиль, сохранив их ID и привязки.

1. Откройте **Рабочее пространство → Инструменты** и редактор установленного
   инструмента AI Support. Замените весь код содержимым
   [approved_instruction_images.py](../integrations/openwebui/approved_instruction_images.py).
   Проверьте в заголовке **`version: 0.3.0`** и сохраните.
   У установленного инструмента ID **`ai_support`**. Его можно сверить в адресе редактора.
2. В Valves инструмента задайте `allowed_knowledge_ids` списком с одним элементом.

   ```json
   ["85cda3aa-b854-4c26-9948-12da742277ef"]
   ```

   Не добавляйте другие базы, даже если ваша учётная запись их видит.
3. В **Панель администратора → Функции** откройте существующую функцию
   **«AI Support — фотографии к ответу автоматически»**. Замените весь код файлом
   [automatic_instruction_images.py](../integrations/openwebui/automatic_instruction_images.py),
   проверьте **`version: 0.5.1`** и сохраните. Включите функцию.
   **Global / Глобальное применение — выключено**.
4. В Valves функции задайте тот же `allowed_knowledge_ids` из шага 2. Списки
   инструмента и Filter должны совпадать. `enabled_model_ids` должен содержать
   профиль `ai-support`. Для установленного инструмента
   `allowed_tool_ids` — `["ai_support"]`. `image_tool_id` обычно остаётся пустым.
   Если `image_tool_id` заполнен, он задаёт разрешённый ID инструмента вместо
   этого списка и должен указывать на тот же доверенный инструмент.
5. В **Рабочее пространство → Модели → ai-support** оставьте в разделе **«Знания»**
   только указанную коллекцию. Уберите из этого профиля другие базы и отдельные
   файлы вне неё.
6. В разделе **«Возможности / Capabilities»** этого профиля снимите общий флажок
   **«Встроенные инструменты»** и сохраните явно выключенное состояние.
   Режим вызова функций **Native** сохраните. В разделе **«Инструменты»** оставьте
   выбранным пользовательский Tool `ai_support`, а в **«Фильтры»** — функцию AI Support.
   Раздел **«Навыки»** профиля должен быть пустым.
7. Замените системный промпт полным текстом
   [openwebui-system-prompt.txt](prompts/openwebui-system-prompt.txt), сохраните профиль
   и начните **новый обычный сохраняемый чат** с `ai-support`.
   Внутренний чат заметки добавляет отдельный контекст и отклоняется этим профилем.

В Open WebUI 0.11.0 выбор функции в списке фильтров модели не включает её автоматически.
Переключатель самой функции в административном списке также должен быть включён.
При ошибке проверки исправьте настройки доверенного инструмента и функции.

Установка выполняется в интерфейсе Open WebUI.

## Что проверяет код

Tool 0.3.0 содержит три доступных метода.

| Метод | Назначение |
| --- | --- |
| `search_approved_instructions(query, count=8)` | Поиск с принудительно заданным разрешённым списком коллекций |
| `read_approved_instruction(file_id)` | Проверка принадлежности и доступа, затем полное чтение источника |
| `show_instruction_images(file_id, image_numbers="auto", offset=0)` | Проверка того же источника и показ исходных фотографий DOCX |

Запрос пользователя, ID чужого файла, папка чата и дополнительные вложения не
расширяют `allowed_knowledge_ids`. Filter проверяет одинаковые списки у себя
и у инструмента, выбор единственного доверенного Tool и знания профиля. Перед
обработкой знаний он исключает чужие коллекции и файловые вложения из контекста
запроса, в том числе из знаний папки. Разрешённые ссылки передаются как проверенные
тип и ID, без пользовательского содержимого, выдающего себя за источник.

Поиск идёт только через `search_approved_instructions`. Встроенные широкие
`query_knowledge_files`, `view_file`, `view_knowledge_file`, списки и grep
не служат запасным способом доступа к другим базам. Ошибка этой настройки должна
остановить запрос до выдачи содержимого вне утверждённого набора.

При чтении исходного DOCX сохраняются полный текст, исходные фотографии и их
описания. Для других поддерживаемых форматов, включая MD, XLSX и PDF, используется
полный извлечённый Open WebUI текст, а `images` в таком результате пустой.
Качество и полнота этого текста зависят от обработчика документов Open WebUI.
При неполном извлечении бот сообщает о недостатке подтверждённых сведений.
Показ фотографий использует встроенные изображения исходных DOCX.

Правила обычного разговора, отказа от раскрытия секретов, исходных фотографий,
ожидания результата шага и продолжения групп сохраняются. При служебной JSON Schema
backend действует прежний служебный режим.

## Исправление поиска в Filter 0.5.1

Если модель в текущем ответе уже успешно вызвала `search_approved_instructions`,
Filter сначала проверяет этот результат: разрешённые `knowledge_ids` должны точно
совпадать, а найденный документ должен соответствовать проблеме по названию и тексту.
Подходящий подтверждённый результат используется перед повторным поиском. Это
исправляет случай, когда первый поиск находил инструкцию, но пустой результат
дублирующего длинного запроса приводил к ложному сообщению об отсутствии ответа.

Выбранный документ затем проходит прежнее полное чтение, проверку принадлежности
коллекции и прав пользователя. Правила фотографий и расположение блоков сохраняются.
Слабые, неоднозначные или не прошедшие проверку результаты не становятся инструкцией.

Если Tool **0.3.0**, промпт и ограничение источников уже настроены с Filter **0.5.0**,
для этого исправления замените только код существующей функции на **0.5.1**.
Сохраните её ID, включённое состояние, Global выключенным и привязку к `ai-support`.
Начните новый сохраняемый чат. Повторно менять Tool, промпт и базу знаний не требуется.

## Ручная проверка границы источников

Выполните проверку в новом сохраняемом чате. Она не требует скриптов или изменений
существующих баз знаний.

1. Отправьте обычную техническую проблему, для которой инструкция есть в утверждённой
   коллекции. Подходит знакомый сценарий, когда PDF открывается в Adobe Acrobat, но при
   печати на HP не печатаются изображения, а из других программ печать нормальная.
2. Раскройте результат `search_approved_instructions`. В `knowledge_ids` должен быть
   **только** `85cda3aa-b854-4c26-9948-12da742277ef`.
3. В результате `read_approved_instruction` проверьте `status="ready"` и
   `source.knowledge_id`, равный этому же ID. Если показаны фотографии, их
   `source.knowledge_id` также должен совпадать. Текст и изображения должны
   соответствовать выбранной утверждённой инструкции.
4. В доступных модели инструментах должны остаться три метода Tool AI Support.
   Отсутствие общих встроенных методов подтверждает настройку интерфейса,
   результаты поиска и проверка источника подтверждают фактический путь выполнения.
5. Отдельно отправьте **«Я забыл пароль от 1С»**. Это обычная проблема поддержки.
   Если утверждённой процедуры восстановления
   доступа в этой коллекции нет, ответ об отсутствии утверждённой инструкции —
   корректный результат. Нельзя искать ответ в другой базе или придумывать сброс.

Дополнительная отрицательная проверка возможна, если у вас уже есть разрешённый
для проверки безобидный контрольный файл в другой коллекции. Передайте его реальный
ID в запросе на чтение через AI Support и раскройте результат инструмента. Даже
если ваша учётная запись имеет к этому файлу доступ, ожидается отказ без содержимого
файла. Если модель отказала только текстом, без вызова инструмента, это не проверяет
границу доступа в коде. Для этого нужен фактический результат метода.
Не используйте для такого теста настоящие секреты, личные инструкции другого
сотрудника или закрытую переписку. Если подходящего контрольного файла нет,
эту дополнительную проверку пропустите.

Эти шаги задают критерии приёмки. Сама инструкция настройки не подтверждает, что
конкретный профиль уже сохранён и проверен на сервере. Для приёмки нужен фактический
результат вашего нового чата.

## Отдельная проверка backend на Debian

Бот через backend использует `OPENWEBUI_KNOWLEDGE_IDS`. Его настройка отдельна от
Workspace Tool и Filter прямого чата. В каталоге приложения на Debian следующая
команда выводит **только список ID** из конфигурации работающего API-контейнера.

```bash
sudo docker compose exec -T api python -c 'import json; from app.core.config import get_settings; print(json.dumps(get_settings().openwebui_knowledge_ids))'
```

Для текущего утверждённого набора ожидается следующий список.

```json
["85cda3aa-b854-4c26-9948-12da742277ef"]
```

Не выводите ради этой проверки весь `.env`, ключи API или полный результат
`docker compose config`. Если API-контейнер остановлен, эта команда не является
подтверждением его настроек. Сначала нужен доступ к работающему контейнеру.
