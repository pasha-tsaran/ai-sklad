# Диагностика SkladTech-bot

В каталоге проекта на Debian проверьте три зависимости отдельно. Эти команды
не отправляют сообщений в Talk.

```bash
sudo docker compose --profile talk exec talk python -m app.talk_worker --check-profile
sudo docker compose --profile talk exec talk python -m app.talk_worker --check-knowledge
sudo docker compose --profile talk exec talk python -m app.talk_worker --check-model
```

`--check-profile` показывает эффективное значение `num_ctx`. Параметр модели
из Open WebUI имеет приоритет. Если он пуст, Talk использует `OPENWEBUI_NUM_CTX`
из окружения. При пустых обоих значениях контекст выбирает провайдер.
Для установки с Qwen и загруженным контекстом 16384 можно задать
`OPENWEBUI_NUM_CTX=16384` в `.env` и пересоздать сервис `talk`.
`--check-model` выполняет настоящее определение темы с лимитом рабочего вызова.

Произвольный вопрос можно проверить в контейнере с действующим индексом.
Команда начинает с пустой истории, выводит использованный источник, количество
картинок и время. Она не создаёт обращение и не отправляет сообщение сотруднику.

```bash
sudo docker compose --profile talk exec talk python -m app.talk_worker --check-question 'Как открыть рабочую почту из браузера?'
```

При `search_method=catalog` агент ранжирует полные тексты локально и видит
названия всех разрешённых документов. Этот режим включается для полного
актуального индекса, когда список названий помещается в контекст поиска.
Если нужен повторный поиск другими словами, агент обращается также к векторному
поиску Open WebUI. Неполный или большой каталог уже при первом запросе использует
гибридный поиск.

В журнале `agent_vector_search` с `outcome=lexical_fallback` означает, что
поиск продолжился по тексту локального каталога. `talk.agent_action_rejected`
показывает причину отклонения действия до отправки. В событии
`talk.model_request_failed` указаны этап HTTP-запроса, лимит чтения и остаток
времени на весь вопрос. У нестримингового запроса `waiting_for_headers`
может включать ожидание всей генерации со стороны Open WebUI.

Если профиль и знания доступны, но проверка модели возвращает `ReadTimeout`,
сравните короткую генерацию напрямую в Ollama и через Open WebUI. Запишите
время загрузки модели, обработки запроса и генерации для холодного и прогретого
запуска. В журнале Talk события одного запроса имеют общий `turn_id`.
Текст запроса, инструкции, пароли и токены в события диагностики не добавляются.

При временном сбое подключения или ошибке шлюза 502–504 агент делает максимум
один повтор запроса к модели. Тайм-аут чтения автоматически не повторяется.
Поиск, определение темы, чтение источников и генерация используют оставшийся
бюджет обработки `TALK_TURN_BUDGET_SECONDS` (по умолчанию 150 секунд).
Это ограничение для сетевых операций, а не гарантия времени доставки сообщения.
Вопросы о типе сканера и принтера можно уточнить без генерации.

Для четырёх проверенных схем печати с ТСД (один Urovo по Bluetooth, один TSC
по Wi-Fi, оба принтера или два TSC по Wi-Fi) Talk умеет вернуть оригинальные
шаги и схему без ожидания модели. Для этого текущий поиск должен найти нужный
файл и его содержимое должно совпасть с проверенной редакцией. Запросы с другими
условиями и изменённые документы обрабатывает обычный агент. Обновление знаний
сразу влияет на проверку редакции. Команда «Продолжить» при сохранённом следующем
шаге сразу передаётся агенту с текущей инструкцией.

Подсказки об удачных поисках действуют до `SUCCESSFUL_RETRIEVAL_TTL_DAYS`
(по умолчанию 30 дней). Worker удаляет просроченные записи при цикле обслуживания
примерно раз в пять минут. Действующие подсказки проверяются по текущему
источнику. Очистка не меняет отзывы, переписку, документы и индекс.

После выпуска проверьте в отдельном чате:

1. «Как настроить сканер?» — один вопрос о типе сканера. После «для штрихкодов»
   бот уточняет требуемое действие.
2. «Как найти большие письма?» — шаги Outlook на 1024 КБ со скриншотами возле шагов.
3. «Да, помогло. Теперь гаснет экран, что делать?» — отзыв сохраняется, бот
   уточняет устройство. После «на компьютере» выдаёт проверку настроек и фото.
4. Запрос про Urovo по Bluetooth не должен получить процедуру для Wi‑Fi.
5. При недоступной модели подходящий типовой сценарий или простое уточнение
   остаются доступны. Для остальных задач бот предлагает обратиться к специалисту.
