# Два независимых помощника с общими настройками

Версия 0.6.0. После получения этого выпуска из GitHub установите обновление на Debian и в Open WebUI.
Текущий профиль `ai-support` сохраняется; создавать `ai-support-talk` не требуется.

## Разделение

| Часть | Open WebUI | Nextcloud Talk |
| --- | --- | --- |
| Диалог | Модель вызывает native Tools | Модель возвращает действия AgentAction |
| Короткая память | История текущего чата Open WebUI | История и состояние обращения в PostgreSQL Debian |
| Долгая память | Только собственные механизмы Open WebUI, если включены | Подтверждённые результаты в PostgreSQL |
| Фото | Tool прикрепляет оригиналы к ответу | Backend проверяет оригиналы и отправляет очередь Talk |
| Общие настройки | Сохранённый профиль ai-support | Копия настроек профиля перед каждым новым сообщением |

Talk не вызывает собеседника `ai-support`: получает настройки профиля и вызывает его
`base_model_id` с собственным контекстом и протоколом. В запросах нет идентификаторов
чатов Open WebUI. UI не подключается к Debian, его обращениям и памяти. Остановка
Debian не отключает UI. Open WebUI остаётся общим провайдером модели и документов;
при его остановке Talk тоже не сможет получить модель/знания.

Одинаковыми являются правила общения, выбранная модель и разрешённые знания.
Это не обещание дословно одинаковых ответов: история, права пользователей, поиск,
исполнение инструментов и способы подготовки письма у каналов различаются.
Долгая память Open WebUI автоматически этим обновлением не создаётся и не мигрирует.

## Что синхронизируется

- `params.system`: полный системный промпт, без локальной копии правил Talk поверх него.
- `base_model_id`: базовая модель; выбирайте непосредственно модель провайдера, не другой профиль/Pipe.
- `meta.knowledge`: коллекции, подключённые к профилю. Новые документы добавляются внутрь этих коллекций.
- Явно сохранённые `temperature`, `top_p`, `top_k`, `repeat_penalty`, `seed`, `num_ctx`.

Прочие параметры, Tools, Functions, их Valves, права, таймауты, лимиты инструментов,
JSON-формат Talk и настройки доставки не копируются. Произвольный новый Tool в UI
не создаёт реализацию инструмента на Debian. Промпт должен быть обычным текстом;
подстановка пользовательских шаблонных переменных UI в Talk не реализована.

Один ответ Talk использует один снимок настроек; редактирование применяется со следующего
сообщения, а не посередине генерации. Каталог также получает актуальный список коллекций.
Перед отправкой технических сообщений/фото очередь повторно проверяет источник с новым
списком коллекций. Уже отправленные сообщения не отзываются.

При ошибке чтения профиля старые настройки не подставляются. Обработчик Talk использует
существующую политику повторов, затем отмечает неудачную обработку; настройки проверяются
командой ниже. Пустой список знаний означает отсутствие доступных инструкций, не доступ ко всем.
Отдельные файлы в `meta.knowledge` не поддерживаются: добавляйте их в коллекции.

## Настроить существующий Open WebUI

Перед изменениями экспортируйте текущий профиль и сохраните код/Valves Tool и Filter для отката.

1. Откройте **Рабочая область → Модели → ai-support → Изменить**. Оставьте текущий ID.
   Базовая модель — существующая `qwen3.6:35b` либо другая модель с рабочими native tools.
2. Замените системный промпт целиком содержимым `docs/prompts/openwebui-system-prompt.txt`.
3. Оставьте утверждённые **коллекции** в разделе знаний. Не добавляйте тот же DOCX отдельно
   к модели. Включите **Function Calling → Native**. Для предсказуемости задайте температуру 0.
   Настройки сохраняйте в профиле модели, а не только в правой панели конкретного чата.
4. В существующем Tool (обычно ID `ai_support`) замените код целиком файлом
   `integrations/openwebui/approved_instruction_images.py`, версия 0.4.0.
   Сохраните ID и привязку к `ai-support`. В Valves установите
   `sync_model_profile=true`, `settings_model_id=ai-support`.
   При этом `allowed_knowledge_ids` остаётся резервом старого режима и не определяет новый список.
5. В существующей Function/Filter фотографий замените код целиком файлом
   `integrations/openwebui/automatic_instruction_images.py`, версия 0.7.0.
   Установите Valve `dialogue_mode=agent`. Фильтр пропускает запросы и ответы, не ведёт
   старый сценарий и не добавляет свои подтверждения. Фото отправляет выбранный моделью Tool.
   Остальные фильтры, если они есть, проверьте отдельно: они не должны подменять диалог.
6. Оставьте привязанным доверенный Tool инструкций; встроенные поиски по другим знаниям,
   интернет, выполнение кода и генерация изображений для этого профиля не нужны.
   Пользователи UI должны иметь доступ к тем же коллекциям, что и сервисная учётная запись Talk.
7. Сохраните изменения. Проверку начните в новом чате; старые диалоги хранят старые ответы/контекст.

Модель без зрения читает текст и подписи. Настройки на схемах нужно описать текстом:
устройства, физические соединения, режим LabelPrint, состояния переключателей 1С.
Само прикрепление фото не означает, что модель распознала его содержимое.

## Настроить Debian после публикации коммита

Сначала перенесите изменения в рабочий Git checkout, проверьте diff, создайте коммит и
отправьте его в GitHub. Если выпуск уже опубликован в GitHub, этот шаг повторять не нужно.
Архив сам по себе не является опубликованным коммитом.

На сервере в существующем checkout `/opt/ai-support`:

```bash
cd /opt/ai-support
git status --short
git rev-parse HEAD
cp .env .env.before-profile-sync
git pull --ff-only
```

Если есть локальные изменения, сначала разберите их; не используйте `git reset --hard`.
Сохраните показанный прежний commit ID для отката. Резервная копия `.env` содержит секреты.
В существующем `.env` установите:

```dotenv
LLM_BACKEND=openwebui
KNOWLEDGE_BACKEND=openwebui
SEED_DEMO_KNOWLEDGE=false
TALK_DIALOGUE_MODE=agent
OPENWEBUI_SYNC_PROFILE=true
OPENWEBUI_PROFILE_ID=ai-support
OPENWEBUI_MODEL=ai-support
```

`OPENWEBUI_BASE_URL`, `OPENWEBUI_API_KEY`, Nextcloud, PostgreSQL и почтовые настройки
оставьте действующими. `OPENWEBUI_MODEL`, `OPENWEBUI_KNOWLEDGE_IDS`, `OPENWEBUI_NUM_CTX`
в новом режиме замещаются значениями профиля; сохраните старые значения для отката.
API-ключ должен принадлежать учётной записи, которой API возвращает `params.system`
профиля: владельцу, администратору с соответствующим доступом или держателю права
редактировать этот профиль. Одного read-доступа в Open WebUI 0.11 может быть недостаточно:
API скрывает `params`. Не выдавайте эти права всем сотрудникам; используйте сервисную учётную запись.

```bash
docker compose --profile talk build
docker compose --profile talk run --rm --no-deps talk python -m app.talk_worker --check-profile
docker compose --profile talk run --rm --no-deps talk python -m app.talk_worker --check-knowledge
```

Обе проверки должны завершиться успешно до замены работающих контейнеров.
`--check-profile` показывает модель, ID коллекций и хеш настроек, но не промпт/ключ.
После успешной проверки:

```bash
docker compose --profile talk up -d
docker compose --profile talk ps
docker compose --profile talk logs --tail=100 talk
curl -fsS http://127.0.0.1:8000/health/ready
```

Новой миграции в 0.6.0 нет: актуальная схема `0011`. `health/ready` проверяет приложение
и БД, не доступ к внешнему профилю; при синхронизации `knowledge_settings_source=profile`,
`knowledge_configured=null`. Доступ к знаниям проверяйте отдельными командами выше.

## Проверка перед использованием сотрудниками

В каждом канале отдельно: печать с ТСД на Urovo по Bluetooth → добавить второй принтер
по Wi-Fi → уточнить текущий шаг → «продолжить» → сообщить результат. Проверьте правильную
схему двух принтеров и оригинальные фото, отсутствие списка найденных документов и
повторного подтверждения задачи. Это обязательная проверка реальной модели: локальные
тесты протоколов не подтверждают качество её выбора инструкций.

Измените тестовую фразу в системном промпте профиля, выполните `--check-profile` и проверьте
изменение `revision`; затем убедитесь, что следующий ответ обоих каналов следует новому правилу.
При замене модели должна измениться строка `model`, при смене коллекции — `knowledge_ids`.
Добавьте тестовый документ в разрешённую коллекцию, дождитесь завершения обработки в Open WebUI
и проверьте поиск в обоих каналах. Сверьте права пользователей, если результаты различаются.

Проверка разделения: сообщите условие задачи только в UI, затем начните новый разговор Talk.
Talk не должен знать это условие. Повторите в обратном направлении.

Откат: восстановите прежние код/настройки UI и `.env`, разверните сохранённый Git commit
и пересоберите контейнеры. Не удаляйте том PostgreSQL. Одного переключения `OPENWEBUI_SYNC_PROFILE=false`
недостаточно для отката UI: его промпт и режим Filter также должны быть согласованы.

Схема API сверена с [исходным кодом Open WebUI 0.11.0](https://github.com/open-webui/open-webui/blob/v0.11.0/backend/open_webui/routers/models.py).
Native tools описаны в [официальной документации](https://docs.openwebui.com/features/extensibility/plugin/tools/).
