# Фотографии инструкций в Open WebUI 0.11.0

Workspace Tool `show_instruction_images` показывает оригинальные иллюстрации из
утверждённого DOCX вместе с соответствующими шагами инструкции. Пользователь не
должен отдельно просить фотографию или выбирать её номер. Инструмент предназначен
для прямого чата с профилем
`ai-support`: встроенные `view_file` и `view_knowledge_file` этой версии возвращают
текст, а подпись «Иллюстрация 1» и карточка источника не являются показом картинки.

Файлы настройки:

- Workspace Tool: [approved_instruction_images.py](../integrations/openwebui/approved_instruction_images.py)
  — чтение утверждённой инструкции и защищённая выдача фотографий.
- Filter: [automatic_instruction_images.py](../integrations/openwebui/automatic_instruction_images.py)
  — автоматическое прикрепление к подготовленному ответу.

Первый файл предназначен для редактора **Инструменты / Tools**, второй — для
**Функции / Functions**. Это не команды для терминала. Обновление Open WebUI,
установка программ на Debian, пересборка контейнеров и миграция БД приложения
для этой настройки не требуются. Документы и состав существующей базы знаний
этим механизмом не изменяются.

## Как работает

1. Модель находит подходящий документ в прикреплённой утверждённой базе знаний и
   читает полный текст и подписи через `read_approved_instruction`, включая условия
   применения и предупреждения.
2. Для относящихся к текущему шагу иллюстраций вызывается `show_instruction_images`
   с настоящим ID DOCX. Известные сведения повторно не запрашиваются; начать
   подходящую процедуру можно без полного опроса пользователя.
3. Инструмент проверяет принадлежность разрешённой коллекции и доступ текущего
   пользователя. Он извлекает встроенные фотографии и их альтернативные описания,
   преобразует изображения в PNG и создаёт приватные файлы в Open WebUI.
4. Инструмент отправляет событие `files`, которое Open WebUI 0.11.0 отображает как
   изображения в сообщении. Подписи возвращаются модели в служебном JSON; модель
   должна дать по ним понятное текстовое пояснение каждой показанной фотографии.

Подключённый Filter выполняет автоматическое прикрепление после подготовки ответа,
если есть однозначный подтверждённый источник и все необходимые разрешения.
Правила промпта определяют диалог, но сами по себе не гарантируют вызов инструмента.
Filter не отправляет все результаты поиска: используется прочитанный, однозначно
цитируемый подходящий DOCX либо текущая закреплённая инструкция. При неоднозначности
нельзя заменять проверку угадыванием документа.
При автоматическом показе Filter сохраняет исходные пронумерованные действия,
включая входные шаги без фотографии, а также подписи и условия утверждённой инструкции.
Он не заменяет процедуру одними подписями и не использует свободно сочинённые
моделью технические действия. Вопрос о текущей кнопке сохраняет тот же источник
и связанные с ним фотографии; продолжение выдаётся после подтверждения прогресса.

Картинки сохраняются из исходной инструкции, а не рисуются заново. Сам факт показа
не означает, что текстовая модель распознала изображение: для объяснения она
использует подготовленные описания. Каждая иллюстрация должна иметь понятное
альтернативное описание в DOCX; комплект «Инструкция-AI» подготовлен с описаниями.

Приватная загрузка не открывает файлы всему серверу. Однако изображение, отправленное
в чат, становится частью переписки: доступ к самой переписке и её дальнейшее
распространение определяются настройками Open WebUI и действиями пользователя.

## Настройка в интерфейсе

Настройку выполняет администратор Open WebUI, которому разрешено создавать инструменты.

1. Откройте **Рабочее пространство → Инструменты** и создайте новый инструмент.
2. Откройте файл
   [approved_instruction_images.py](../integrations/openwebui/approved_instruction_images.py),
   скопируйте всё его содержимое в редактор инструмента и сохраните. Не вставляйте
   этот код в сообщение чата или системный промпт модели. Если инструмент уже
   установлен, замените его код целиком: новая версия содержит оба метода —
   `read_approved_instruction` и `show_instruction_images`. В заголовке файла
   должна быть версия Tool **0.2.0**.
3. В настройках **Valves** этого инструмента проверьте `allowed_knowledge_ids`.
   Для нашей базы знаний используется список:

   ```json
   ["85cda3aa-b854-4c26-9948-12da742277ef"]
   ```

   Это ID утверждённой коллекции, не `file_id` отдельной инструкции. При переносе
   на другой сервер укажите фактический ID новой коллекции. Не добавляйте чужие
   коллекции, чтобы обойти отказ в доступе.
4. Откройте **Рабочее пространство → Модели → ai-support**. Прикрепите к этому
   профилю утверждённую базу знаний и созданный инструмент. Не подключайте инструмент
   ко всем моделям сервера.
5. Выберите **Native** для вызова функций. Включите необходимые встроенные категории
   **База знаний / Knowledge Base** и **Файлы / Files**. Генерацию изображений для
   профиля оставьте выключенной: она не нужна для показа оригинальных инструкций.
6. Замените системный промпт полным текстом из
   [openwebui-system-prompt.txt](prompts/openwebui-system-prompt.txt) и сохраните профиль.
7. Создайте **новый сохраняемый чат** с профилем `ai-support`, чтобы проверить
   сохранённые инструменты и настройки профиля. Для этой проверки выключите
   временный режим чата.

Название и расположение переключателей зависят от языка интерфейса. Не создавайте
API-ключи и не указывайте их в коде инструмента, параметрах модели или ссылках
изображений: используется текущий пользователь Open WebUI.

## Автоматическое прикрепление: Filter

Сначала обновите Workspace Tool по предыдущему разделу. Filter использует методы
из уже выбранного для текущего профиля инструмента, а не отдельные API-ключи.

1. Откройте **Панель администратора → Функции → Новая функция**:
   [редактор новой функции](https://ai.collant.ru/admin/functions/create).
   Не создавайте второй Workspace Tool для этого файла.
2. Вставьте целиком
   [automatic_instruction_images.py](../integrations/openwebui/automatic_instruction_images.py)
   в редактор функции и нажмите **«Сохранить и создать»**.
3. В [списке функций](https://ai.collant.ru/admin/functions) включите переключатель
   созданной функции. **Global / Глобальное применение** оставьте выключенным.
4. В Valves проверьте `enabled_model_ids=["ai-support"]` и `priority=20`.
   `image_tool_id` можно оставить пустым: Filter использует выбранный в этом
   запросе инструмент с парой методов `read_approved_instruction` и
   `show_instruction_images`. Если такой инструмент определить однозначно
   нельзя, автоматический показ не должен подменяться произвольным инструментом.
5. В редакторе модели `ai-support`, под выбором **Инструментов** и **Навыков**,
   найдите **«Фильтры» / Select Filter** и выберите созданную функцию. Она должна
   применяться только к `ai-support`; Workspace Tool при этом также остаётся
   выбранным в настройках профиля.
6. Сохраните профиль и начните новый сохраняемый чат под пользователем с доступом
   к утверждённой коллекции. Проверьте обычное обращение без слов «покажи фото».

Filter рассчитан на сохраняемый чат с владельцем и активным сеансом Open WebUI.
Он пропускает служебные запросы backend с JSON Schema, API-вызовы без этого
контекста, временные чаты и каналы. Установка не расширяет права на коллекции
и не подключает механизм ко всем моделям. Обновление старого Tool без установки
Filter изменяет пакетную выдачу, но не делает автоматический вызов надёжным.

## Вызов инструмента

Для чтения источника используется `read_approved_instruction(file_id)`. Он
возвращает `status="ready"`, `source`, полный `content` и список `images` с
номерами и подписями. Чтение не прикрепляет фотографии. При отказе возвращается
ошибка без текста документа; обходить её другим способом чтения нельзя.

Для показа используется `show_instruction_images`. Служебные параметры:

| Параметр | Значение |
| --- | --- |
| `file_id` | Реальный ID прочитанного DOCX, полученный при поиске или чтении файла |
| `image_numbers` | `"auto"` по умолчанию; внутренний выбор относящихся к шагу номеров через запятую также поддерживается |
| `offset` | Модель использует только `0`; подтверждённое продолжение по `next_offset` выполняет автоматический Filter |

Нумерация иллюстраций начинается с **1** и следует порядку изображений в исходном
DOCX. Если указаны номера `"3,1"`, картинки всё равно показываются в порядке исходного
документа: сначала первая, затем третья. За один вызов показывается не более **6**
фотографий из выбранной последовательности. `"auto"` и `"all"` начинают с первой
группы, а не предлагают пользователю выбрать номера. Если фотографий больше,
результат содержит `has_more=true` и `next_offset`. После объяснения текущих действий
помощник уточняет, выполнены ли они, и ожидает ответа. Следующая группа отправляется
только автоматическим Filter после подтверждения прогресса по сохранённому состоянию.
Модель не должна сама увеличивать смещение или последовательно вызывать все группы.
Filter сохраняет те же `file_id` и `image_numbers`; смещение относится к той же
выбранной последовательности. Служебный допуск к продолжению пользователь не заполняет.

Технически оставшиеся фотографии не являются обязательными следующими действиями:
учитываются применимость раздела и текущий шаг. Установка уже установленного драйвера,
логотип, справочный рисунок или действие только для ИТ не должны предлагаться просто
потому, что идут дальше в документе. Номера фотографий, смещение, UUID и размер группы
остаются служебными параметрами. Сотруднику не требуется выбирать их или искать ID.
Модель должна найти документ самостоятельно и передать его настоящий ID. Имя файла,
ID коллекции и придуманный UUID для `file_id` не подходят.

При успехе возвращается `status="displayed"` и `displayed=true`. Поле `source`
содержит `file_id`, `filename`, `knowledge_id` и `sha256`; элементы `images` — номер,
описание и данные созданного изображения (`number`, `caption`, `filename`, `file_id`).
Результат также содержит `offset`, `next_offset`, `has_more`, `total_images` и
`progress_message` для остановки перед продолжением.
Пользователь должен увидеть сами изображения и подготовленные описания, а не этот
служебный JSON. Успешный поиск документа или вызов `view_file` ещё не подтверждает
отправку фотографии. Проверяйте результат именно `show_instruction_images` и
фактическое отображение изображения. Модель должна объяснить показанные картинки
по возвращённым подписям, не повторяя уже выведенные пояснения и изображения.

При отказе возвращается `status="error"`, `displayed=false`, `code` и `message`.
Например, неверный выбор номера, отсутствие иллюстраций, неподдерживаемый документ
или отказ в доступе не являются разрешением подставить другую картинку.
`status="awaiting_confirmation"` и `displayed=false` означают остановку перед
следующей группой: самостоятельный вызов продолжения моделью не разрешён. Номера
фотографий у сотрудника не запрашиваются, повторные вызовы не выполняются.
После подтверждения выполненных действий продолжение обрабатывает Filter.
Если после приватной загрузки произошёл сбой отправки события, результат
`delivery_unknown` означает, что показ не подтверждён. Не повторяйте такой вызов
автоматически: проверьте чат и повторите только по явной просьбе пользователя.
Повторные вызовы создают новые приватные копии изображений; кеш повторной выдачи
не используется.

В сохраняемом чате повторные вызовы внутри одного ответа сохраняют предыдущие
вложения и добавляют новые. Инструмент сверяет файлы текущего ответа через служебный
контекст Open WebUI; эти данные модель и пользователь не подставляют вручную.
Для временного чата такой синхронизации с сохранённой историей нет: рекомендуем
одну отправку выбранных фотографий за ответ и сохраняемый чат для проверки.

Ограничения чтения: DOCX до 30 МБ, до 60 исходных иллюстраций; одна картинка —
до 8 МБ и 16 млн пикселей, все нормализованные картинки — до 32 МБ.
Каждая встроенная иллюстрация должна иметь непустой альтернативный текст. OCR и
придумывание подписей инструментом не выполняются. Читаются иллюстрации в основном
теле DOCX; изображения из колонтитулов не извлекаются. При необходимости подготовьте
исходный DOCX перед повторной загрузкой в утверждённую коллекцию.

## Проверка без скриптов

Начните новый сохраняемый чат и отправьте обычное сообщение для уже проверенного
сценария с инструкцией № 05:

> В Adobe Acrobat PDF открывается, но при печати на HP не печатаются изображения.
> Из других программ принтер печатает нормально.

Проверяйте следующие результаты:

- Модель действительно вызывает инструменты поиска и читает подходящий документ.
  В нашем комплекте этому сценарию соответствует инструкция № 05 с одной фотографией.
  Источник должен относиться к проблеме печати изображений из Acrobat, а не только
  содержать знакомое слово.
- Для фотографии выполняется `show_instruction_images` с реальным ID этого DOCX
  и первой подходящей группой. Его может вызвать модель либо настроенный Filter
  после подготовки ответа; в последнем случае проверяйте запись автоматического
  прикрепления и фактические вложения. Отдельная просьба показать картинку и выбор
  её номера не нужны. Показ не подменяется вызовом `view_file` или `display_file`.
- В ответе показана настоящая картинка, а не только «Иллюстрация 1», описание либо
  карточка цитируемого DOCX. Сравните её с первой фотографией исходной инструкции.
- Подпись и объяснение соответствуют показанному изображению. Технические действия
  взяты из прочитанной утверждённой инструкции, включая исходный входной шаг
  открытия окна печати, а не только описание единственного скриншота Acrobat.

Для инструкции № 05 запрос второй иллюстрации должен завершиться честным отказом:
в этом исходном документе только одна фотография. Проверку нескольких существующих
иллюстраций выполняйте на другой утверждённой инструкции, где они действительно есть.
Отсутствие фотографий или ошибка доступа не должны превращаться в выдуманный совет.

Для проверки продолжения диалога используйте знакомый сценарий настройки сканера:

> Работаю в 1С АДРЕС 1.0.53, драйвер сканера уже установлен. Нужно настроить сканер
> штрихкодов для моего рабочего места.

Ожидается пользовательская часть инструкции № 33 с исходными фотографиями к
соответствующим действиям. Затем напишите: «Не могу найти Операции». Помощник должен
остаться на текущем шаге той же инструкции, показать нужную иллюстрацию и объяснить
элементы по её описанию. Он не должен переходить к ИТ_01, сбросу, установке драйвера
или листам программирующих штрихкодов. При неподтверждённом отличии интерфейса
допустим один необходимый вопрос; при отсутствии ответа в источнике — честное
сообщение о недостатке сведений и необходимости помощи специалиста.

На утверждённой инструкции с более чем шестью подходящими фотографиями проверьте,
что первая группа показывается без предложения выбирать номера, а продолжение
отправляется после подтверждения выполненных действий. В одном ответе не должны
автоматически выводиться все группы подряд.

Если тест не прошёл, раскройте результат выполнения и проверьте код обоих компонентов,
состояние функции, её привязку к профилю, сохранённые Valves, реальный `file_id`, доступ
пользователя, исходный DOCX и наличие описаний.
Ошибка чтения или доступа не доказывает, что нужной инструкции нет в базе знаний.

## Границы решения

- Поддерживаются встроенные фотографии из DOCX с описаниями. Это не универсальный
  просмотрщик PDF/XLSX и не генератор изображений.
- Инструмент действует в прямом чате Open WebUI. Его установка не подключает память
  PostgreSQL приложения, учёт попыток, отправку заявок и Nextcloud Talk.
- Debian backend имеет собственное чтение DOCX, снимки иллюстраций и выдачу файлов в
  Talk. Этот путь проверяется отдельно; Workspace Tool его не заменяет.
- Если backend передал служебную JSON Schema, действует его служебный режим.
  Модель не должна вызывать инструмент показа картинок вместо ответа по схеме.
- Автоматический Filter пропускает неоднозначный или неподтверждённый источник.
  Он не превращает найденный фрагмент или название файла в утверждённую инструкцию.
  После ошибки отправки автоматический повтор недопустим: часть вложений уже могла
  попасть в чат. Для проверки нужен результат механизма и изображение в ответе.
- Реальная доступность инструмента и качество выбора инструкции проверяются на
  установленном Open WebUI 0.11.0 после настройки. Проверки кода не заменяют этот тест.
