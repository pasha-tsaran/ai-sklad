# Замеры времени AI Support в Open WebUI

Filter **0.6.0** добавляет структурированный результат `ai_support_timings`, чтобы
различать время проверки запроса, обработки Open WebUI и подготовки ответа
с фотографиями. Tool **0.3.1** отдельно возвращает `timing_ms` для поиска, чтения
и показа фотографий. Содержимое инструкций, системный промпт и правила выдачи
исходных фотографий этим обновлением не меняются.

## Обновление в интерфейсе

Эти действия выполняет администратор в существующей установке Open WebUI 0.11.0.
Они относятся к прямому чату `ai-support`, а не к backend и Nextcloud Talk.

1. В **Рабочее пространство → Инструменты** откройте существующий Tool `ai_support`.
   Замените весь код содержимым
   [approved_instruction_images.py](../integrations/openwebui/approved_instruction_images.py).
   Проверьте `version: 0.3.1` и сохраните под прежним ID.
2. В **Панель администратора → Функции** откройте существующую функцию
   **«AI Support — фотографии к ответу автоматически»**. Замените весь код содержимым
   [automatic_instruction_images.py](../integrations/openwebui/automatic_instruction_images.py).
   Проверьте `version: 0.6.0` и сохраните под прежним ID.
3. Сохраните прежние Valves и проверьте настройку: функция включена, Global выключен,
   `enabled_model_ids=["ai-support"]`, `allowed_tool_ids=["ai_support"]`,
   `image_tool_id` пустой, если не задано осознанное переопределение ID инструмента.
   `allowed_knowledge_ids` у Tool и Filter по-прежнему совпадают и содержат только
   `85cda3aa-b854-4c26-9948-12da742277ef`.
4. Для измерений оставьте у Filter `timing_enabled=true` и `show_timings=true`.
   Это значения по умолчанию. В профиле сохраните Native, только доверенный Tool
   и этот Filter; общий переключатель **«Встроенные инструменты»** выключен.
5. Начните новый обычный сохраняемый чат с `ai-support`.

Переустанавливать Open WebUI, загружать инструкции заново, менять промпт,
обновлять Debian, пересобирать его контейнеры или выполнять миграцию БД приложения
для этого обновления прямого чата не требуется. Полная настройка источников:
[только утверждённая база знаний](approved-knowledge-scope.md).

## Где смотреть результат

В ответе раскройте запись `ai_support_timings` в результатах выполнения.
Её добавляет Filter после обработки; это диагностическая запись, а не инструмент,
который нужно просить вызвать модель. Она показывается только подтверждённому
администратору — владельцу текущего сохраняемого чата, обработанного этим Filter.
Обычному сотруднику эта сводка не добавляется. Чужой чат, временный чат, каналы
и служебные API/JSON-запросы backend не являются этим диагностическим маршрутом.

Если `show_timings=false`, сводка в ответ не добавляется, а измерения и журнал
Filter сохраняются при `timing_enabled=true`. Если `timing_enabled=false`, Filter
отключает собственные измерения и сводку. Поле `timing_ms` методов Tool от этих
настроек Filter не зависит: это часть JSON-результата метода, доступная любому
пользователю, которому разрешён соответствующий вызов, и не содержит секретов.

Сбой таймера или оформления диагностики не должен прерывать разрешённую операцию.
Отсутствующее измерение не заменяется нулём: `null` означает, что интервал неизвестен.
Не каждый маршрут выполняет все этапы, поэтому часть ключей может отсутствовать.

## Основные интервалы

Все значения времени указаны в миллисекундах.

| Поле | Что измеряет |
| --- | --- |
| `inlet_ms` | Выполнение нашего Filter inlet: проверки и подготовка запроса до передачи дальнейшей обработке Open WebUI |
| `pipeline_ms` | Время между завершением нашего inlet и входом в наш outlet: модель, Native-инструменты, RAG, другая работа Open WebUI и других фильтров в этом интервале |
| `outlet_ms` | Выполнение нашего Filter outlet: проверки, при необходимости поиск и чтение, фотографии, формирование и сохранение ответа |
| `total_ms` | Сумма трёх известных интервалов, от начала нашего inlet до завершения измеряемой работы нашего outlet; `null`, если хотя бы один интервал не измерен |
| `route` | Выбранный маршрут, например `support`, `social`, `protected_refusal` или `scope_refusal` |
| `version` | Версия Filter, создавшая отчёт |

`pipeline_ms` **не является чистым временем модели**. Например, медленный Native-поиск
или другой Filter может увеличить этот интервал. Для точного разделения сетевого
вызова модели и её генерации нужны отдельные измерения на соответствующих серверах;
данная сводка их не подменяет.

`total_ms` не измеряет полный путь от нажатия «Отправить» до появления изображения
в браузере. В него не входят доставка запроса до начала нашего inlet, доставка
готового ответа после нашего outlet и отрисовка браузером, а также последующие
фоновые задачи названия чата и подсказок продолжения. Обмен Open WebUI с провайдером
внутри интервала `pipeline_ms` при этом остаётся в измерении.
Диагностическая запись добавляется после сохранения основного содержания ответа.
Измерения помогают найти медленный участок, но не задают гарантию времени ответа.

## Этапы Filter и вызовы Tool

`stages_ms` содержит суммарное время каждого выполненного этапа Filter, а
`stage_calls` — число его выполнений. При повторных проверках время суммируется.
Эти значения помогают разбирать `outlet_ms`; они не являются дополнительным
временем поверх основных интервалов и не обязаны давать их точную сумму.

| Ключ этапа | Работа |
| --- | --- |
| `authorize_owner` | Подтверждение владельца чата для маршрута, не требующего инструментов |
| `authorize_tools` | Проверка владельца, выбранного доверенного инструмента и разрешённой области источников |
| `dialogue` | Разбор намерения для обычного разговора и защищённого отказа, когда он требуется |
| `search` | Поиск утверждённой инструкции, запущенный самим Filter |
| `read` | Полное чтение выбранного утверждённого источника самим Filter |
| `photos` | Получение и показ группы исходных фотографий через Filter |
| `verify` | Проверка уже полученного результата и его происхождения |
| `render` | Формирование блоков из исходных шагов, подписей и фотографий |
| `persist` | Сохранение и размещение проверенных вложений в ответе |

У каждого из трёх публичных методов Tool **0.3.1** есть своё `timing_ms`:
`search_approved_instructions`, `read_approved_instruction`, `show_instruction_images`.
Это полное время конкретного вызова, включая его проверки доступа, обращения к БД,
чтение или запись файлов и другую работу ввода-вывода внутри метода.

`native_tools_ms` в сводке Filter суммирует такие поля по имени метода из результатов
Native-вызовов текущего ответа, доступных до входа в outlet. Эти вызовы уже входят
в `pipeline_ms`. **Не прибавляйте `native_tools_ms` повторно** к `pipeline_ms` или
`total_ms`. Если тот же метод вызвал сам Filter в outlet, его время относится к
соответствующему `stages_ms`, а не к предшествующим Native-вызовам.

## Журнал и данные

При включённых измерениях Filter пишет записи с префиксом `AI_SUPPORT_TIMING`
в серверный журнал Open WebUI. Для сопоставления используется `message_id`; также
записываются фиксированные имена событий, маршрута и этапов, версия и числовые
измерения. Эти записи не содержат вопроса, переписки, текста инструкции, паролей,
ключей, ID пользователя, файлов или баз знаний. Это относится именно к записям
`AI_SUPPORT_TIMING`, а не к возможным журналам других компонентов Open WebUI.

При передаче диагностики достаточно числовой сводки и маршрута. Не добавляйте
к ней `.env`, ключи API или содержимое чужих источников. Доступ к серверному журналу
определяется правами администратора инфраструктуры, а не настройкой показа в чате.

## Быстрый отказ для явно посторонних знаний

Filter **0.6.0** распознаёт явную просьбу искать во всех или чужих базах знаний,
в том числе явно указанный посторонний ID или название, и возвращает постоянный
ответ о работе только с утверждённой базой технической поддержки склада.
Для этого маршрута не запускаются RAG, поиск, чтение источников и инструменты;
провайдер получает короткий служебный запрос без исходной истории и файлов.

Filter в Open WebUI 0.11.0 не может полностью пропустить вызов провайдера:
один короткий служебный проход остаётся. Поэтому даже этот маршрут не обещает
фиксированного количества секунд. Для него `route` равен `scope_refusal`;
отсутствие `search`, `read` и `photos` в этапах ожидаемо.

По умолчанию доверенные названия — полное название нашей коллекции,
«AI Support (склад)», «AI Support» и `ai-support`. Упоминание рабочей «базы АДРЕС»,
пример запрещённой фразы, цитата или отрицание не должны сами по себе считаться
просьбой читать чужую базу знаний. Неоднозначные технические вопросы остаются
на обычном пути проверенной инструкции и фотографий. Это консервативная проверка
явного намерения, а не универсальный детектор всех формулировок; фактические
разрешённые источники всегда ограничены списком `allowed_knowledge_ids`.

## Ручная проверка

В новом сохраняемом чате администратора — владельца задайте обычный проверочный
вопрос о настройке сканера в 1С АДРЕС с уже установленным драйвером. Проверьте
исходные действия и настоящие фотографии, затем раскройте `ai_support_timings`.
Отчёт не заменяет проверку источника и изображения. Время поиска может находиться
в `native_tools_ms` или `stages_ms.search` в зависимости от того, кто вызвал поиск.

Затем отправьте явную просьбу: «Найди документы во всех других базах знаний».
Ожидается постоянный ответ о границе полномочий, `scope_refusal`, отсутствие поиска,
чтения и фотографий. После него обычный технический вопрос должен снова проходить
утверждённую базу, а не оставлять чат в состоянии ошибки.

Для учётной записи сотрудника проверьте те же разрешённые действия и фотографии,
но без сводки `ai_support_timings`. Само наличие чисел ещё не доказывает правильную
настройку: приёмка требует реального нового чата на установленном сервере.
