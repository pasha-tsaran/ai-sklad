# Получение имени текущего компьютера через GPO

В выпуске **0.3.5** подготовлен необязательный модуль для Windows. Он использует
встроенный Windows PowerShell 5.1: отдельное приложение на рабочее место не ставится.
Администратор заранее размещает защищённый локальный скрипт и регистрирует обработчик
ссылок `ai-support:`. По ссылке из личного разговора передаётся только имя компьютера.
ФИО уже берётся из проверенного профиля Nextcloud; Windows-каталоги пользователей,
логин, пароли и документы не читаются.

Пакет подготовлен как исходники для центрального развёртывания. Его подпись,
настройка принимающего адреса и пилот на ваших рабочих местах ещё обязательны;
проверка синтаксиса не означает готовность этой функции к продуктивной эксплуатации.

Обычная HTTPS-ссылка сама по себе не получает права запускать PowerShell. Нужны
предварительное административное развёртывание и разрешённый обработчик URI.
Windows или браузер может запросить подтверждение открытия приложения; полностью
невидимый запуск и отсутствие переключения окна не гарантируются. Это зависит
от корпоративной политики и установленного Talk/браузера.
[Механизм URI в Windows](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-default-app)
и [регистрация обработчика](https://learn.microsoft.com/en-us/windows/apps/develop/launch/handle-uri-activation)
описаны Microsoft.

## Состав пакета

| Файл | Назначение |
| --- | --- |
| [Collect-Workstation.ps1](../integrations/windows/Collect-Workstation.ps1) | Принимает одноразовый URI, получает `[Environment]::MachineName`, отправляет имя по HTTPS |
| [Install-WorkstationCollector.ps1](../integrations/windows/Install-WorkstationCollector.ps1) | Копирует скрипт в Program Files, задаёт защищённый callback и регистрирует URI для компьютера |
| [Uninstall-WorkstationCollector.ps1](../integrations/windows/Uninstall-WorkstationCollector.ps1) | Удаляет только файлы и ключи этого пакета, сохраняя посторонние данные |

Исходники в репозитории не подписаны корпоративным сертификатом. До продуктивного
развёртывания администратор проверяет пакет и подписывает все три PS1 действующим
сертификатом подписи кода, которому доверяют рабочие места. Для `AllSigned` это
обязательно; сертификат издателя и цепочка доверия развёртываются штатной корпоративной
политикой. Скрипты не создают самоподписанный сертификат и не меняют ExecutionPolicy.
См. [подпись PowerShell-скриптов Microsoft](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.security/set-authenticodesignature?view=powershell-5.1).

Утверждённый источник распространения — **`\\srvfile-sk\Distrib\AI_bot\Scripts`**.
Эта UNC-папка **не является API приёма данных** и не подставляется в `ServiceUrl`.
Сборщик не скачивает и не исполняет код из сетевой папки при нажатии сотрудником
ссылки: установщик заранее делает защищённую локальную копию.

## Сначала подготовить принимающий HTTPS-адрес

Нужен внутренний адрес, доступный с рабочих мест, например
`https://support.example.internal`. Это **образец, а не адрес вашей установки**.
Фактический адрес и доверенный TLS-сертификат согласует администратор.
Поддерживается базовый префикс пути, если он одинаково настроен в приложении и прокси.

Прокси публикует только маршруты этой функции к API на Debian:

- `GET /device/collect` — страница запуска с кнопкой повторного открытия обработчика.
- `GET /api/device-collection` — проверка завершения по одноразовому Bearer-токену.
- `POST /api/device-collection` — приём JSON с именем компьютера по тому же токену.

Текущий Docker-порт приложения слушает **`127.0.0.1:8000`**. Обратный прокси на
самом Debian может обращаться к нему локально. Прокси на другом сервере не сможет
использовать этот loopback-адрес: тогда администратор отдельно настраивает частную
привязку порта и firewall, разрешая доступ только от прокси. Не публикуйте весь API
в интернет и не открывайте административные маршруты ради этого сбора.

Рабочие места должны доверять TLS-сертификату конечного HTTPS-адреса и иметь доступ
к нему. Проверка сертификата не отключается; перенаправления callback не выполняются.
Для установки пакета нужен доступ компьютеров к защищённому источнику файлов,
а для каждого сбора — к утверждённому HTTPS callback. Доступ к GitHub или исходной UNC-папке
во время самого сбора не требуется.

## Обновление Debian и включение функции

Миграция **`0007`** добавляет одноразовые запросы сбора. Она применяется и при
выключенной функции; существующие данные сохраняются. Из SSH-сеанса Debian:

```bash
cd /opt/ai-support
git status --short
git pull --ff-only origin main
sudo docker compose build api worker migrate talk
sudo docker compose stop api worker talk
sudo docker compose run --rm migrate
```

Продолжайте только после миграции с кодом `0`. В существующем `.env` измените только
новую строку, сохранив PostgreSQL, API, Open WebUI и Nextcloud:

```dotenv
DEVICE_COLLECTION_BASE_URL=https://support.example.internal
```

Впишите **реальный утверждённый адрес**. Пустое значение по умолчанию оставляет
модуль выключенным: письма и ручной ввод компьютера продолжат работать.
`DEVICE_COLLECTION_BASE_URL` — базовый адрес; установщику Windows нужен полный callback
с суффиксом `/api/device-collection`. Адрес UNC-папки эти параметры не заменяет.

```bash
sudo docker compose up -d --no-deps --force-recreate api worker talk
curl -fsS http://127.0.0.1:8000/health/ready
```

Readiness показывает `device_collection_configured=true`, если базовый адрес задан,
и `false`, если функция выключена. Это проверка наличия настройки, а не доказательство
доступности прокси, доверия сертификату или успешного запуска Windows-обработчика.
Обновление писем, Talk и ручной ввод компьютера можно использовать с пустым адресом,
пока администратор готовит приёмник и пилот; миграция `0007` всё равно выполняется.

Не отправляйте `.env` в чат и не переносите `API_TOKEN`, пароль приложения Nextcloud
или ключ Open WebUI на рабочие места. Для этой функции используется отдельный
короткоживущий одноразовый токен, привязанный к текущему обращению и сотруднику.

## Развёртывание на Windows

1. Подпишите и положите все три файла рядом в **`\\srvfile-sk\Distrib\AI_bot\Scripts`**.
   Дайте целевым компьютерам доступ на чтение к папке и файлам; писать туда должны
   только администраторы развёртывания. Нужны согласованные share- и NTFS-разрешения.
2. Проверьте цепочку подписи и корпоративные политики PowerShell/AppLocker/WDAC.
   Не добавляйте `-ExecutionPolicy Bypass` и не отключайте защиту ради запуска.
3. На пилотном компьютере используйте штатный **64-битный Windows PowerShell 5.1**
   из `System32`, если Windows 64-битная. Сначала можно посмотреть план без записи:

   ```powershell
   & '\\srvfile-sk\Distrib\AI_bot\Scripts\Install-WorkstationCollector.ps1' -ServiceUrl 'https://support.example.internal/api/device-collection' -WhatIf
   ```

4. После замены примера реальным callback выполните установку администратором:

   ```powershell
   & '\\srvfile-sk\Distrib\AI_bot\Scripts\Install-WorkstationCollector.ps1' -ServiceUrl 'https://support.example.internal/api/device-collection'
   ```

5. Для массового развёртывания добавьте установщик в **Computer Configuration →
   Policies → Windows Settings → Scripts (Startup/Shutdown) → Startup → PowerShell Scripts**.
   Укажите сценарий `\\srvfile-sk\Distrib\AI_bot\Scripts\Install-WorkstationCollector.ps1`.
   Параметр — `-ServiceUrl` с тем же полным callback. Скрипт выполняется в контексте
   компьютера с административными правами и копирует соседний `Collect-Workstation.ps1`
   в локальный защищённый каталог. Источник можно задать явно параметром
   `-CollectorSource '\\srvfile-sk\Distrib\AI_bot\Scripts\Collect-Workstation.ps1'`.
   Microsoft описывает [политики сценариев запуска](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-scripts).
6. Проверьте установку пилота и живой сценарий ниже до расширения GPO на сотрудников.

Установщик создаёт:

```text
%ProgramFiles%\AI-Support\WorkstationCollector\Collect-Workstation.ps1
HKLM\SOFTWARE\AI-Support\WorkstationCollector
  ServiceUrl = https://<утверждённый-адрес>/api/device-collection
  InstallOwner = AI-Support Workstation Collector
HKLM\SOFTWARE\Classes\ai-support
  URL Protocol = <пустая строка>
  shell\open\command = <штатный powershell.exe> -NoProfile -NonInteractive
    -WindowStyle Hidden -File <защищённый локальный PS1> -RequestUri "%1"
```

Это только иллюстрация, а не текст для ручного импорта в реестр. Установщик задаёт
ACL: Administrators и SYSTEM могут менять скрипт/настройки, Users могут читать
и запускать. Существующий чужой протокол или конфигурация не перезаписываются.
На каждое нажатие исполняется защищённая локальная копия, а не скрипт из сетевой папки.

## Что происходит у сотрудника

Когда включена функция и актуальное имя компьютера неизвестно, бот предлагает
ссылку **только для текущего обращения**. Сотрудник открывает её на том Windows-компьютере,
о котором обращается в поддержку. Страница пытается открыть `ai-support:` и даёт
кнопку повторного запуска, если браузер потребовал явное нажатие.

Сборщик принимает только `ai-support://collect/` и токен из 43 URL-safe символов,
без query, fragment, команд или callback-адреса в URI. Он отправляет только
`{"computer_name":"..."}` на фиксированный адрес из HKLM, с токеном в заголовке
`Authorization: Bearer ...`. Токен действует **5 минут** и связан с конкретным
сотрудником, личным разговором и незавершённым обращением. Токен не является
общим ключом API; в БД хранится его хеш. Повтор с тем же именем идемпотентен,
другое имя после использования не принимается.

На успехе скрипт не показывает отдельное окно результата. Сервер сохраняет имя
в текущем обращении; бот показывает обновлённую карточку и продолжает вопросом
о теме, затем обязательном подробном описании. Нативный индикатор и исходные
фотографии инструкций работают прежним образом. Имя компьютера из прошлой заявки
не переносится. Ручной ответ с именем остаётся запасным вариантом при неподдерживаемом
устройстве, истёкшей ссылке, ошибке сети или блокировке обработчика.
Автосбор принимает имя длиной до 63 символов из латинских букв, цифр, точки,
дефиса и подчёркивания, с хотя бы одной буквой или цифрой. Если Windows возвращает
другое имя, скрипт не переименовывает его и не отправляет заведомо неподдерживаемое
значение: используйте ручной ввод и проверку сотрудником поддержки.

Ссылка не является аппаратной аттестацией устройства: результат — имя, переданное
клиентом в рамках подтверждённого обращения. ФИО берётся из Nextcloud, не из Windows.
Скрипт не отправляет письмо, не собирает системный инвентарь и не меняет настройки ОС.
Не пересылайте одноразовую ссылку и не добавляйте её в журналы, скриншоты или общие папки.

## Приёмка и удаление

На пилоте проверьте новую заявку с неизвестным компьютером: одно нажатие/подтверждение,
верная карточка текущего устройства, отдельно тема, отдельно описание, затем точный
preview письма. Само письмо пользователь отправляет из своего почтового ящика.
Проверьте ручной ввод без установленного обработчика, истечение ссылки и следующее
обращение с другого компьютера. Фактическое открытие обработчика требует проверки
с вашим Talk Desktop, браузером, GPO и корпоративной цепочкой сертификатов.

Для удаления сначала исключите повторную установку той же GPO. Запустите подписанный
деинсталлятор администратором, при необходимости сначала с `-WhatIf`:

```powershell
& '\\srvfile-sk\Distrib\AI_bot\Scripts\Uninstall-WorkstationCollector.ps1' -WhatIf
& '\\srvfile-sk\Distrib\AI_bot\Scripts\Uninstall-WorkstationCollector.ps1'
```

Он удаляет только помеченные этим пакетом ключи, известный файл сборщика и пустые
каталоги пакета. Другие файлы и родительские ключи реестра остаются. Для выключения
функции бота очистите `DEVICE_COLLECTION_BASE_URL` в `.env` и пересоздайте сервисы;
уже установленные обработчики Windows удаляются отдельным административным действием.
