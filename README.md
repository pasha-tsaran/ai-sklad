# AI Support

Open WebUI хранит утверждённые инструкции и обращается к моделям на Mac Studio.
Debian VM запускает API, worker и PostgreSQL, управляет обращениями, обратной связью,
лимитом пяти решений и отправкой заявки в поддержку. Модели на VM не загружаются.
Nextcloud Talk и SMTP подготовлены, по умолчанию работают в `mock`.
Почта только отправляет заявки; чтения ответов из почты нет.

## Знания и модели

```dotenv
LLM_BACKEND=openwebui
OPENWEBUI_BASE_URL=https://ai.collant.ru
OPENWEBUI_API_KEY=<ключ сервисной учётной записи>
OPENWEBUI_MODEL=ai-support
KNOWLEDGE_BACKEND=openwebui
OPENWEBUI_KNOWLEDGE_IDS=["id-утвержденной-коллекции"]
SEED_DEMO_KNOWLEDGE=false
NEXTCLOUD_BACKEND=mock
MAIL_BACKEND=mock
```

Профиль `ai-support` в Open WebUI должен использовать модель на Mac Studio, без
инструментов, веб-поиска и выполняющих действия pipelines. Сервисной учётной записи
выдайте доступ только к необходимым коллекциям и файлам. Модель меняется в профиле
или через `OPENWEBUI_MODEL`. Embeddings/обработку документов настраивают в Open WebUI
с внутренним сервером моделей; приложение настройки Open WebUI не меняет.

В Knowledge загружайте **один законченный вариант решения на файл**, включая
условия выполнения и ограничения по оборудованию. Членство в разрешённой коллекции
означает допуск к выдаче ботом, поэтому добавляйте только проверенные инструкции.

Backend передаёт разрешённые коллекции через `files` в `/api/chat/completions`.
Модель выбирает ID файла либо сообщает об отсутствии решения. Backend повторно
проверяет членство файла в коллекциях. Для MD используется полный извлечённый текст,
для DOCX и XLSX — оригинальный файл через `/api/v1/files/{id}/content`.
DOCX читается вместе с встроенными фотографиями и их подписями, XLSX — по всем
заполненным строкам и ячейкам без выполнения формул. Произвольные технические шаги
и адреса картинок, придуманные моделью, не выводятся.
Выбор релевантного файла зависит от качества модели и RAG — нужен тест на вашем корпусе.

Файлы длиннее `KNOWLEDGE_MAX_CHARS` (20000 по умолчанию) не обрезаются и не выдаются:
разделите их на законченные инструкции. Исходный Office-файл ограничен
`KNOWLEDGE_MAX_FILE_BYTES` (25 МБ). DOCX должен содержать обычные встроенные PNG,
JPEG или GIF с непустым альтернативным описанием каждой фотографии (`descr`
в `wp:docPr`); то же описание должно быть видимым текстом рядом с фото.
Комплект «Инструкция-AI» подготовлен в этом формате. Внешние изображения, VML,
макросы и формулы Excel не исполняются. Одна фотография ограничена 8 МБ и 16 млн
пикселей, инструкция — 60 фотографиями и 32 МБ декодированных изображений.
Проверьте качество поискового текста в Open WebUI. Неизвестный ID/ошибка API не
заменяются локальными демо-инструкциями. Пустой список коллекций означает отсутствие
знаний. При отсутствии решения бот запрашивает форму без расходования попыток.

Файлы с префиксами `ИТ_` и `СПРАВОЧНИК_` можно хранить в той же коллекции и
просматривать в Open WebUI. Backend исключает их из автоматического выбора
пользовательского решения: прошивка, изменение политик и большой справочник не
должны выдаваться как обычная инструкция сотруднику. Разрешение для автоматической
выдачи меняется осознанным редактированием и переименованием файла.

### Фотографии в ответах

Backend сохраняет текст, фотографии, подписи и SHA-256 с обращением в PostgreSQL.
Основной ответ и каждое фото — отдельные сообщения в последовательной очереди.
Модель выбирает инструкцию по описаниям; визуальное распознавание фотографий
отдельной моделью не требуется. Изображения не генерируются и не восстанавливаются
из текста. В `GET /api/incidents/{id}` у сообщений есть `attachments` с подписями и
адресами. Получение картинки по этому адресу требует тот же `API_TOKEN` и проверку
владения обращением. API-токен и ключ Open WebUI не включаются в ссылки.

Для реальных вложений Talk нужна существующая служебная учётная запись Nextcloud
Files с паролем приложения. API webhook-ботов не загружает файлы. Backend загружает
фото через WebDAV и делится им только с разрешённой комнатой (`shareType=10`),
добавляя подпись. Служебный пользователь должен быть участником этих комнат;
используйте Talk с поддержкой `media-caption` (Talk 18+).

```dotenv
NEXTCLOUD_FILES_USERNAME=<ID служебного пользователя Nextcloud>
NEXTCLOUD_FILES_APP_PASSWORD=<пароль приложения Nextcloud Files>
```

Эти значения отличаются от `NEXTCLOUD_BOT_SECRET`. После настройки пересоздайте
API и worker. При `mock` фото доступны через API без подключения Nextcloud.
При отсутствии прав или ошибке отправки фото остаётся в очереди со статусом
`UNKNOWN`; оператор проверяет Nextcloud перед повтором. Уже отправленные текст
и фотографии автоматически не дублируются. Файлы хранятся в служебном аккаунте
в отдельных каталогах комнат; публичные ссылки не создаются. Размер БД и
резервных копий вырастет на размер сохранённых иллюстраций.

Описание API: [оригинальные файлы Open WebUI](https://docs.openwebui.com/features/workspace/knowledge/#api-access),
[передача файлов в Talk](https://nextcloud-talk.readthedocs.io/en/stable/chat/#share-a-file-to-the-chat).

Один файл не повторяется в обращении даже после редактирования. PostgreSQL хранит
снимки источников и SHA-256 для истории, не второй поисковый индекс. Старые таблицы
pgvector сохранены для совместимости. Снимки `openwebui-reference` не участвуют
в локальном поиске и не требуют embedding-модели на VM.

## Диалог, LangChain и память

Полный системный промпт для профиля модели: [docs/prompts/openwebui-system-prompt.txt](docs/prompts/openwebui-system-prompt.txt).
Замените им прежний текст в «Модели → ai-support → Системный промпт» и сохраните профиль.
В прямом чате Open WebUI промпт отдельно задаёт порядок: поиск по прикреплённым знаниям,
получение настоящего ID файла, чтение источника, затем ответ. Имя файла и ID коллекции
не заменяют `file_id`. Проверяйте реальные результаты инструментов и карточки источников,
а не утверждение модели «документ найден». Используются Native, выбранный доверенный
Tool и доступ учётной записи к коллекции; общий переключатель встроенных инструментов выключен.
Прямой чат не проходит через API Debian: память PostgreSQL, попытки и очередь фотографий
backend проверяются отдельно через приложение. Обновление только этого текста промпта
не требует пересборки образов или миграции БД.
Для показа оригинальных фотографий в прямом чате установленного Open WebUI 0.11.0
предусмотрен Workspace Tool `show_instruction_images`:
[настройка и ручная проверка](docs/openwebui-instruction-images.md).
Он подключается к профилю `ai-support`, читает полный источник через
`read_approved_instruction` и извлекает иллюстрации из разрешённых DOCX;
обновление Open WebUI и установка программ на Debian для этого пути не нужны.
Целевое поведение — фотографии автоматически рядом с текущими шагами, короткие
группы действий и продолжение после подтверждения результата. Для автоматического
прикрепления дополнительно подключите Filter `automatic_instruction_images.py`
через Functions только к этому профилю. Промпт сам по себе не гарантирует вызов;
проверяйте реальное прикрепление изображения и подтверждённый источник.
Filter начиная с **0.2.0** сам выполняет разрешённый поиск и полное чтение, если модель
пропустила вызовы знаний; слабый или неоднозначный результат не заменяется
техническими догадками модели. Видимый статус проверки помогает отличить работу
обработчика от ответа без источника. Filter **0.3.0** формирует блоки с исходными
действиями, описанием и одной соответствующей фотографией под текстом. Приватные
PNG сохраняются, проверенные изображения текущего ответа перемещаются из верхней
галереи в свои блоки, прочие вложения сохраняются. Для перехода обновите код
существующей функции, сохранив её ID, включённое состояние и привязку к `ai-support`.
[Порядок настройки](docs/openwebui-instruction-images.md).
Filter **0.4.0** добавляет отдельный разговорный маршрут и проверку доступных
возможностей до вызова модели. Технические реплики проходят прежний путь источников
и фотографий, неоднозначные сообщения направляются в техническую ветку. Бытовая
беседа сохраняет текущую инструкцию и продолжение. Для API и Talk тот же принцип
реализован отдельной типизированной стадией backend, его служебные запросы явно
передают `tools: []`. [Диалог, настройка ограничений и проверка](docs/dialogue-and-safety.md).
Filter **0.4.1** сохраняет защищённый отказ как обычный завершённый ответ и позволяет
продолжить чат. Исходная запрещённая просьба заменяется для провайдера постоянным
служебным текстом без истории, файлов и инструментов. Для старого отказа с ошибкой
после обновления функции используйте повторную генерацию ответа.
Tool **0.3.0** и Filter **0.5.1** ограничивают поиск и чтение коллекциями из одинакового
`allowed_knowledge_ids`. Встроенные инструменты профиля выключаются целиком.
Три метода доверенного инструмента выполняют поиск, чтение и показ фотографий
после проверки коллекции и прав пользователя. Источники папки и вложений ограничиваются
тем же списком. [Обновление и проверка области знаний](docs/approved-knowledge-scope.md).
Filter **0.5.1** проверяет и использует релевантный успешный результат утверждённого
поиска из текущего ответа модели до повторного запроса. Это устраняет ложное
отсутствие инструкции после пустого дублирующего поиска; чтение и проверки доступа сохраняются.
Продолжение между группами выполняет Filter по подтверждению пользователя;
модель сама не увеличивает смещение и не отправляет все группы подряд.
Проверяйте его в новом сохраняемом чате; для временного чата рекомендуется одна
отправка фотографий за ответ.
Общие правила дополнительно включены в служебные шаблоны backend: один только промпт
в профиле не подключает память. LangChain Core собирает цепочку шаблон → существующий
HTTP-адаптер Open WebUI → строгая проверка JSON. Новые облачные модели не требуются;
удалённая трассировка отключена.

История из PostgreSQL передаётся при анализе проблемы, выборе инструкции и уточнениях.
Короткая память включает последние сообщения, ограниченное резюме ранних сообщений
пользователя и результаты попыток. Резюме детерминировано, хранится в `incident_memory`
и переживает перезапуск worker. При сокращении контекста исходная переписка сохраняется.
Долгая память `resolution_memory` содержит только явно сообщённые пользователем тип
проблемы/модель оборудования из обращений, решение которых он оценил как успешное.
Она не содержит инструкций, фотографий, произвольного текста переписки или секретов.
Известные форматы токенов и значения с метками пароля/ключа маскируются в контексте.
Автоматическое распознавание секретов не гарантирует обнаружения произвольного текста;
не передавайте учётные данные в чат.

```dotenv
MEMORY_MAX_MESSAGES=12
MEMORY_MAX_CHARS=12000
MEMORY_RETENTION_DAYS=90
```

`MEMORY_MAX_CHARS` ограничивает компактно сериализованный контекст истории, а не полный
запрос с инструкцией и не число токенов модели. Исторические записи используются только
для уточнений; они не доказывают применимость прежнего решения к новому обращению.
Просроченная долгая память удаляется при следующей загрузке контекста этого пользователя;
исходный журнал обращений этим не удаляется. Пользовательские исправления в текущем
диалоге важнее истории. Единственный источник технических действий — текущая утверждённая
база знаний Open WebUI; второй векторный индекс на Debian не создаётся.

В ожидании обратной связи можно задавать вопросы вроде «где эта кнопка?» через тот же
`POST /api/chat` или Talk. Worker обрабатывает `CLARIFY`, оставляя исходную попытку открытой.
Модель выбирает только существующие индексы фрагментов/иллюстраций; backend воспроизводит
исходный текст и оригинальные фотографии с подписями. Полная инструкция сохраняется в
ответе рядом с выбранным фрагментом, чтобы не потерять условия и предупреждения.
Произвольный технический текст модели не выводится. При отсутствии ответа бот прямо
говорит, что переданная инструкция базы знаний его не содержит. При сбое сервиса он
сообщает о сбое. Уточнения не увеличивают счётчик и не запускают отправку заявки.
Оценку по прежнему `attempt_id` можно отправить после завершения обработки уточнения.
Номер попытки, переходы состояния, форма и отправка письма остаются под контролем backend.

Перед повторной выдачей проверяются локальное утверждение/версия и, для Open WebUI,
текущее членство файла в разрешённой коллекции и хеш содержимого оригинала. Удалённый
или изменённый документ не подменяется историческим снимком.

Память изолирована по аутентифицированному пользователю и текущему обращению. В Talk
сохраняется изоляция по серверу, комнате и пользователю: сведения не переносятся между
комнатами. REST с общим `API_TOKEN` представляет одного тестового `mock-employee`;
он не предназначен для определения разных сотрудников в продуктивной интеграции.

Обновление добавляет миграцию `0004` и зависимости LangChain. Пересоберите образы и
выполните миграцию перед запуском API/worker, используя команды ниже. Для первой
сборки нужен доступ к реестру образов и индексу Python-пакетов.

## Обновление Debian VM

Не выполняйте `down -v`.
Оставьте прежние `API_TOKEN` и `POSTGRES_PASSWORD`, добавьте настройки знаний.
Не копируйте `.env.example` поверх действующего `.env`.

```bash
cd /opt/ai-support
git pull --ff-only
sudo docker compose stop api worker
sudo docker compose build api worker migrate
sudo docker compose run --rm migrate
sudo docker compose up -d
sudo docker compose ps -a
curl -fsS http://127.0.0.1:8000/health/ready
```

Миграция `0002` добавляет адресацию Talk и очередь исходящих сообщений, `0003` —
снимки фотографий с подписями, `0004` — память диалога и историю подтверждённых фактов.
Обращения сохраняются. `migrate` должен завершиться
с кодом 0. API слушает `127.0.0.1:8000`, БД
наружу не опубликована. Readiness проверяет БД и показывает выбранные режимы,
**не проверяет доступность Open WebUI/Talk/SMTP**. Нужны отдельные сквозные проверки.

## Подключение Nextcloud Talk позже

Требуется capability `bots-v1` (Talk 17.1 / Nextcloud 27.1 и новее).
Администратор Nextcloud регистрирует бота через `occ talk:bot:install` и добавляет
его в разрешённые комнаты; параметры смотрите через `occ talk:bot:install --help`.
Webhook: `https://<внутренний-адрес-бота>/api/integrations/nextcloud/talk`.
Внутренний HTTPS reverse proxy должен проксировать на VM только этот путь.
Остальные `/api/*` и `/docs` административные, сотрудникам не публикуются.
REST `API_TOKEN` даёт доступ к тестовому пользователю и статистике, не заменяет SSO.

```dotenv
NEXTCLOUD_BACKEND=talk
NEXTCLOUD_BASE_URL=https://<ваш-nextcloud>
NEXTCLOUD_BOT_SECRET=<общий-секрет-не-менее-32-символов>
NEXTCLOUD_ALLOWED_ROOMS=["token-комнаты"]
```

Используйте закрытую комнату для отдельного сотрудника и поддержки: бот отвечает
в ту же комнату, все её участники видят сообщения. Разделение обращений по пользователю
не делает общую комнату приватной. Webhook проверяет HMAC и backend URL, принимает
зарегистрированных пользователей из разрешённых комнат, игнорирует ботов и служебные
события. Повтор message ID не создаёт второе обращение или feedback.

Для оценки скопируйте команду из ответа: `Помогло <код попытки>` или
`Не помогло <код попытки>`. Код защищает следующую попытку от запоздавшего ответа.
Для обращения к человеку отправьте `оператор`. По запросу формы отправьте:

```text
ФИО: Иванов Иван Иванович
Логин: ivanov
Компьютер: WS-001
Тема: Принтер не печатает
Описание: Кабель проверен
```

Описание необязательно. Вложения не скачиваются. После изменения `.env`:
`sudo docker compose up -d --force-recreate api worker`.

## Подключение исходящей почты позже

```dotenv
MAIL_BACKEND=smtp
SUPPORT_EMAIL=<адрес-службы-поддержки>
SMTP_HOST=<внутренний-smtp>
SMTP_PORT=587
SMTP_SECURITY=starttls
SMTP_FROM=<адрес-бота>
SMTP_USERNAME=<логин-если-нужен>
SMTP_PASSWORD=<пароль-если-нужен>
```

Для implicit TLS используйте `SMTP_SECURITY=ssl` и порт сервера (обычно 465).
Сертификаты проверяются. Получатель задаётся конфигурацией, не моделью/пользователем.
Письмо содержит форму, полную историю, результаты попыток и summary LLM;
ошибка summary не блокирует отправку. `SENT` означает приём SMTP-сервером,
не создание тикета в сторонней системе.

## Неопределённая доставка

Talk/SMTP сохраняют `SENDING` до сетевого запроса. Тайм-аут или рестарт во время
отправки дают `UNKNOWN`: автоматического повтора нет, сообщение могло быть принято.
В Talk последующие сообщения этой комнаты ждут разрешения неопределённости;
остальные комнаты продолжают работу. Список без персональных данных:

```bash
sudo docker compose exec worker python -m app.deliveries mail
sudo docker compose exec worker python -m app.deliveries talk
```

Сверьте доставку на почтовом сервере/в Talk. Если подтверждена доставка:
`sudo docker compose exec worker python -m app.deliveries mail --id <ID> --action mark-sent`.
Если подтверждено отсутствие доставки, используйте `--action retry`.
Для Talk замените `mail` на `talk`. Действие записывается в аудит.
Повтор без проверки может создать дубль.

## Сеть без общего интернета

Для сборки нужны registry образов и источники Python-зависимостей. В рабочем режиме
VM нужны внутренние DNS/NTP, Open WebUI HTTPS, Nextcloud HTTPS и SMTP.
Nextcloud должен видеть webhook. Open WebUI должен видеть модели на Mac Studio.
Прямой доступ VM к Mac Studio при этой схеме не нужен. Закрытие общего интернета
не должно закрывать эти внутренние маршруты.

## Проверки

```bash
sudo docker compose exec api python -m pytest -q
sudo docker compose exec api ruff check app tests scripts migrations
sudo docker compose exec -e TEST_POSTGRES=1 api python -m pytest tests/test_postgres.py::test_migrations_match_models tests/test_postgres.py::test_worker_singleton_lock -q
```

Основные тесты используют временную SQLite и подменённые HTTP/SMTP-клиенты, реальные
сообщения не отправляют. PostgreSQL-проверки нужно отдельно запустить на VM.
Реальные версии Open WebUI/Talk и качество выбора инструкций проверяются после настройки.

Учебный сценарий отдельно: `LLM_BACKEND=mock`, `KNOWLEDGE_BACKEND=demo`,
`SEED_DEMO_KNOWLEDGE=true`, интеграции `mock`, затем `python scripts/demo.py`.
Он создаёт историю и меняет статистику. Демо-инструкции не корпоративные.
Контракты REST находятся в `/docs`; POST требует Bearer `API_TOKEN` и `Idempotency-Key`.

Протоколы: [Open WebUI API](https://docs.openwebui.com/reference/api-endpoints/),
[Nextcloud Talk bots](https://nextcloud-talk.readthedocs.io/en/latest/bots/).
